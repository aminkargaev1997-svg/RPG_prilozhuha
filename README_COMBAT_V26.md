# RPG Creators v26 — фундамент боевой системы

## Суть

Кубики только физические. Приложение НЕ генерирует случайные броски, не решает попадание и не списывает HP автоматически. Эта версия добавляет очередь инициативы, два действия за ход, редактируемый ведущим ход боя, историю действий и LAN-синхронизацию. Механики атаки, применения лечения, расчёта урона и статусов будут расширяться в v27–v28.

## Использование

1. Мастер создаёт LAN-комнату, игроки подключаются с персонажами.
2. На странице **⚔ Бой** мастер нажимает **Подготовить бой**. Подключённые игроки появятся в списке автоматически.
3. Мастер при желании добавляет на бой врагов с карты или обычных участников с произвольным именем и бонусом инициативы.
4. Каждый игрок бросает **настоящий d20** и записывает число 1–20. Бонус инициативы мастер вычисляет из листа персонажа: floor((Ловкость − 10)/2) + дополнительный бонус из листа D&D. Для мобов мастер вручную вводит результат d20 и бонус.
5. Когда все броски записаны, мастер нажимает **Начать бой**. Порядок: итоговая инициатива по убыванию, при равенстве — больший бонус, далее прежний порядок участников.
6. Текущий игрок выбирает «Перемещение», «Атака», «Способность», «Предмет» или «Защита / помощь». Каждое действие списывает один из двух слотов. Необязательный комментарий фиксируется в боевом журнале. Фактический бросок кубика остаётся на столе.
7. Выбрав «Перемещение», игрок получает право использовать джойстик в текущем ходу (дистанция пока контролируется мастером). Ход передаётся вручную. После последнего участника начинается новый раунд.
8. Мастер может принудительно переключить ход, вернуться к предыдущему, вернуть действие, начать новый бой или закончить текущий.

## Сетевые правила

- Единственный источник правды — экземпляр LanSession на устройстве мастера. Клиент отправляет запросы (`combat_command`), но не может напрямую заменить состояние боя.
- Сервер сверяет личность бросающего и текущего действующего участника, диапазон броска и максимум два действия. Инициативный бонус игрока рассчитывается **на сервере** из текущего снимка персонажа; клиентский бонус не принимается как истина.
- В ходе боя джойстик игрока с активным участием выключен до своего хода и выбора «Перемещение». Сервер независимо отвергает лишние пакеты движения.
- Состояние сохраняется в SharedPreferences у ведущего по ID комнаты. При переподключении игрока участник восстанавливается по стабильной идентичности персонажа.
- Мастер может перемещать игроков на карте в обход ограничений, чтобы исправлять ситуации.
- После окончания боя очередь очищается; HP, инвентарь и способности не изменяются.

## Ограничения v26

- HP и эффекты не изменяются автоматически при расходе действия: в этой версии можно вписать «8 урона по гоблину» и вручную поправить HP в уже существующем интерфейсе.
- Открытие инвентаря/способностей не тратит действие автоматически: действие фиксируется в разделе «Бой» после решения игрока и мастера.
- Движение по карте пока не имеет сетки, радиуса и однократной за ход траектории. «Перемещение» разрешает использовать джойстик до конца хода; дистанцию проверяет мастер.
- Мастер управляет передвижением мобов и отслеживает их атаки вручную. Состояния и длительность эффектов — будущий этап.
- Данная версия не прошла Android Gradle сборку в рабочем окружении (Android SDK/Gradle отсутствует). Логический движок был отдельно скомпилирован и протестирован через `kotlinc`.

## Исходники

- `CombatEngine.kt` — модель, проверки, инициативы, порядок, действия и раунды.
- `CombatStorage.kt` — JSON-синхронизация и сохранение у мастера.
- `CombatScreen.kt` — единый UI подготовки и боя.
- `LanNetworking.kt`, `LanGameScreen.kt` — LAN-протокол, состояние и интеграция.
